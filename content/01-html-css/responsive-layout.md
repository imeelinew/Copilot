# 移动端适配是怎么做的？

## 30 秒回答

轻购是纯移动端 H5，我的方案分四层：viewport 正确设置、布局交给 flex 和 Vant 组件、尺寸用相对单位、细节用媒体查询兜底。思路是"结构用弹性布局解决，尺寸用相对单位缩放，极端情况才写断点"。城市视图是后台项目，用 Ant Design 的响应式栅格加 ResizeObserver 处理图表容器，思路类似但目标设备不同。

## 标准回答

先说 viewport：移动端 H5 要设置 meta viewport 为设备宽度、初始缩放为一，这是所有适配的前提，少了它后面的方案都会失真。

尺寸方案上，rem 和 vw 是两条主流路线。rem 依赖 JS 或 CSS 动态计算根字号，团队里通常配合 postcss 插件把设计稿 px 换算过去；vw 直接用视口百分比，不需要运行时 JS，兼容性现在也没问题。我在项目里倾向 vw 或视口相关的方案，配合 max-width 约束极端屏幕，避免大屏上元素无限放大。

结构上，电商页面大量用 flex：商品列表、购物车行、底部操作栏都是弹性布局，内容多少都不破版。组件层面用 Vant，它自身对移动端的适配是成熟的，我主要保证自定义样式和它协调。

细节层面有几个真实会遇到的问题：高分屏的 1px 边框，用伪元素加 transform 缩放或直接用较浅的颜色弱化；iPhone 底部安全区用 env(safe-area-inset-bottom) 垫高；图片用固定宽高比占位，避免加载时跳动。

测试上我不只看模拟器，会用开发者工具的多机型模式过一遍常见尺寸，真机再验证触控目标和滚动体验。

## 回答要点

- 先说 viewport，再讲 rem/vw 的选择和取舍。
- 带出 1px、安全区、图片占位这些真实细节，比背方案可信。
- 后台项目（Ant Design 栅格）和 H5 方案分开说。
