# 怎么理解语义化标签？

## 30 秒回答

语义化就是用表达内容的标签代替清一色的 div 和 span：导航用 nav、区块用 section、列表用 ul、可点击的动作按钮用 button。价值有三层：可访问性上读屏软件和键盘用户能理解结构；SEO 上爬虫更容易识别页面主次；可维护性上读代码就知道每块是什么。我在项目里坚持表单和按钮用原生元素加自定义样式，而不是 div 模拟，因为原生控件自带键盘焦点和触发行为。

## 标准回答

我最能说明语义化价值的一个例子是 button 和 div 加点击事件的差别。原生 button 有键盘焦点、支持 Enter 和 Space 触发、disabled 状态自动阻断交互、读屏软件会播报它是按钮；换成 div，这四件事全要手动补，实际项目里经常漏。所以语义化的第一个收益是"浏览器和辅助技术已经把行为写好了"，白拿的可访问性。

第二层是结构和 SEO。header、nav、main、footer 让页面骨架一目了然，爬虫对标题层级和导航区的识别也更可靠。对后台管理系统 SEO 不敏感，但结构清晰依然降低了维护成本——接手别人代码时，语义化的结构比满屏 div 好读得多。

第三层是内容模型。列表数据用 ul/li 或 table，而不是一堆 div 排出来的"看起来像列表"，样式和结构分离后，改版时只需要动 CSS。

当然语义化也有边界：不是为了标签而标签，一个 section 里只有一个段落时硬套 article 就过度了。我的原则是先用对内容模型，再考虑样式实现。

## 回答要点

- 用 button 对比 div 的四个自带行为，把抽象话题落地。
- 三层收益：可访问性、结构 SEO、可维护性。
- 说明不过度语义化的边界，避免背书感。
