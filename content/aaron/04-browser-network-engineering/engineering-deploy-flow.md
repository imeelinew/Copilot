# 项目是怎么打包上线的？

## 核心回答

前端上线本质就一句话：build 出一堆静态文件，放到服务器上让 Nginx 托管，接口靠反代转发给后端。流程按环境走：开发环境自己调，测试环境给测试同学验，预发环境连着生产的数据做最后一道检查，没问题才合到生产。环境之间的差别主要是接口地址和功能开关，这些抽成环境变量，构建时按环境注入，绝不上线前手动改代码。

我自己的项目就是这么走的：git push 之后 CI 跑 npm run build，产物部署到 Nginx。Nginx 干三件事：托管静态资源、history 路由匹配不到时回退到 index.html、/api 反代到后端服务。

出问题要能回去。发新版时旧产物保留着，回滚就是把指向切回去或者重新部署上一个版本，所以版本化发布比直接覆盖靠谱得多。

## 展开回答

两个常追问的点。一是预发和测试的区别：测试环境连测试数据，随便造；预发连的是生产数据库，配置尽量和生产一致，用来验"连真数据会不会出事"。二是发完版用户还看到旧页面，多半是 HTML 被缓存了，所以发布策略是 HTML 不缓存或短缓存，带 hash 的 js、css 长缓存——内容一变文件名就变，天然更新。走 CDN 的话还要主动刷新节点缓存。

灰度发布可以当加分项：新版本先放给一部分用户，盯着报错率和性能指标，没问题再全量，出事影响面也小。
