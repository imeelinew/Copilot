# 瀑布流布局怎么实现？

## 核心回答

主流做法是 JS 算列。图片统一列宽、高度自适应，先按容器宽度除以列宽算出列数，再建一个数组存每列的当前高度；新图片来一张，就找高度最小的那一列塞进去，然后把那列的高度加上这张图的高。全部放完，容器高度取最大的列高。核心逻辑就一句：每次都往最矮的列里放。

最容易踩的坑是高度未知。图片没加载完根本不知道多高，直接塞进去布局全乱、页面乱跳。解法是让后端把宽高一起返回，先用宽高比撑好占位再去加载；拿不到就监听 onload，加载完再插入，加载中放个固定占位块。

加载更多用触底加载：以前是监听 scroll 算滚动位置，现在我更愿意用 IntersectionObserver 放个哨兵元素，进视口就请求下一页，不用自己算，配个防抖和"没有更多"的兜底就行。

## 展开回答

纯 CSS 也有方案，但各有硬伤。columns 多列布局最省事，缺点是内容按列排序，不是用户习惯的从左到右按行排；grid 拉伸行高能做，但会出现空洞，得开 dense 去填，顺序更不可控。所以对展示顺序有要求的业务还是 JS 方案。

细节上还有两件事：resize 时列数变了要重新分一遍；性能上图片全配懒加载，视口外的先不请求，别一口气渲染几百张。
