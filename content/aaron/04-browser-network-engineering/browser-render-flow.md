# 浏览器是怎么渲染页面的？

## 核心回答

主流程四步。解析 HTML 生成 DOM 树，解析 CSS 生成 CSSOM，两者合成渲染树——只收可见节点，display: none 这种不会进去。然后是布局，递归算出每个节点的准确位置和大小，这一步也叫重排。最后绘制，把节点画出来，再交给合成线程合成到屏幕上。

有两个阻塞点我会主动讲。CSS 不阻塞 DOM 解析，但没解析完就建不了渲染树，页面会白屏，所以样式表放头部、尽早加载。js 更狠，默认既阻塞 DOM 解析又阻塞渲染，因为脚本可能改 DOM、还可能读样式，浏览器干脆停下来等它。所以没有依赖顺序的脚本我会加 defer 或 async：async 是下载完立刻执行，会打断解析，适合统计这种独立脚本；defer 是下载完先不执行，等 DOM 解析完按顺序跑，适合主逻辑。

再往深一层是分层合成。浏览器把页面拆成若干图层，transform、opacity 这类属性只走合成，不碰布局和绘制，所以动画用它们做才不卡。

## 展开回答

这道题后面基本必接追问。白屏和首屏优化能接性能优化那一套：关键 CSS 内联、脚本 defer、图片懒加载，本质都是在缩短这条渲染路径。js 为什么阻塞解析也能展开：除了可能改 DOM，浏览器还要防止脚本读到"算了一半"的样式，宁可停下来。

实际开发里我感知最深的就是别用 js 硬改样式触发整条路径重算，能用 transform 就用 transform，让改动停在合成阶段。
