# 了解哪些设计模式？说说单例和观察者

## 核心回答

常用的几个我都用 JS 写过最小实现：单例、工厂、代理、装饰器、观察者。单例是保证一个类全程只有一个实例，对外给一个统一的获取入口，实现思路就是第一次创建后把实例缓存起来，之后再要直接返回缓存，典型场景是全局弹窗、登录框，或者封装的全局请求实例。补充一点，ES Module 本身天然就是单例，模块第一次 import 之后就被缓存了，到处引入拿到的都是同一份。

工厂是把创建对象的过程收进一个工厂函数或类里，调用方只管传参数拿结果，不用关心内部怎么 new 的，创建逻辑要改只改工厂一处。代理是不直接访问目标对象，中间隔一层代理，在访问前后加控制，比如拦截读取做日志、权限校验、缓存，Vue3 的响应式底层就是用 Proxy 拦截 get 和 set。装饰器是不动原来的类或对象，在外面套一层来加功能，比如订单对象套上优惠券装饰器去加价，React 的高阶组件就是这个思路。

观察者是一对多的依赖关系：目标对象自己维护一个观察者列表，提供添加和删除，状态一变就遍历列表挨个调 update。它和发布订阅的区别我专门梳理过：观察者模式里目标和观察者是直接认识的，观察者把自己注册到目标身上，目标直接调用观察者的方法，耦合在双方之间；发布订阅中间多了一个事件中心，发布方只管往中心发事件，订阅方只管在中心订阅，双方互相不认识，靠事件名匹配，解耦得更彻底。Vue2 响应式里 Dep 收集 Watcher 是观察者，Vue 的事件总线 EventBus 是发布订阅。

## 展开回答

这几个用一句话区分：单例管全局只有一个，工厂管怎么创建，代理管访问时加控制，装饰器管不改动的前提下加功能，观察者管状态变了通知别人。它们在前端框架里全是现成的例子：Vue3 响应式是代理，Vue2 响应式是观察者，高阶组件是装饰器，项目里封装的 axios 实例是单例。

面试时我一般按「是什么、解决什么问题、在哪见过」的顺序讲一个模式，再主动对比观察者和发布订阅，这块最容易混，能讲清楚算加分。
