# JS 垃圾回收是怎么进行的？

## 核心回答

JS 的内存不用手动释放，引擎里的垃圾回收器会定期清理。主流算法是标记清除：回收器从根出发，全局对象、当前调用栈这些，凡是还能被访问到的对象都标记成活的；一圈走完，没被标到的就是垃圾，直接清掉回收内存。所以判断垃圾的标准是还能不能被访问到，而不是引用多不多。

早期还有引用计数：每个值记录被引用的次数，归零就回收。它有个致命缺陷，循环引用解不了，两个对象互相引用，计数永远不降到零，内存就一直占着。所以现代引擎基本都改成了标记清除。

对写代码的指导意义就是：不再用的东西要把引用断掉。定时器记得 clear、事件监听记得移除、闭包别长期抱着大对象，不然 GC 会认为它还被需要，不回收，这就是内存泄漏。

## 展开回答

常见的泄漏点：忘记清理的 setInterval、组件卸载后没移除的监听器、不小心挂到全局的临时变量、闭包长期持有的 DOM 引用。React 里 useEffect 返回的清理函数就是专门干这个的。

另外 WeakMap、WeakSet 的键是弱引用，不阻止垃圾回收，对象没有别的引用了就能被清掉，适合做临时缓存。排查泄漏用 Chrome 的 Memory 面板，操作前后各拍一次堆快照对比，看哪类对象只增不减。
