# 用户连续发送两条消息，或者离开页面，流式请求怎么办？

## 核心回答

当前每次发送都会创建一条独立的助手占位消息，后续事件按消息 ID 更新，所以两个请求的文本不会直接拼到同一个气泡里。但发送按钮只检查输入是否为空，没有在生成期间禁用，也没有 AbortController；因此后发请求可能先结束，第二次请求拿到的历史还可能缺少第一条正在生成的内容。用户离开页面后，代码也没有主动取消读取，所以不能说浏览器请求或服务端生成一定停止。如果产品要求严格一问一答，我会在生成期间限制发送并提供停止按钮；如果允许并发，就要保存独立上下文快照、请求 ID 和控制器。取消浏览器请求是否停止服务端计算，还需要接口协议配合。

## 回答要点

- 当前每次发送都会创建一条独立的助手占位消息，后续事件按消息 ID 更新，所以两个请求的文本不会直接拼到同一个气泡里。
- 但发送按钮只检查输入是否为空，没有在生成期间禁用，也没有 AbortController；
- 因此后发请求可能先结束，第二次请求拿到的历史还可能缺少第一条正在生成的内容。
- 用户离开页面后，代码也没有主动取消读取，所以不能说浏览器请求或服务端生成一定停止。
