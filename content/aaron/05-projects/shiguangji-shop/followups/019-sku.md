# 追问：SKU 为什么用 Set 收集规格？把规格拼成字符串匹配有什么问题？

## 核心回答

接口给出的每个 SKU 都是一组完整属性，例如“颜色:黑;尺码:M”。前端把每条组合按分号和冒号拆开，再用 Set 收集每个属性下不重复的选项，这样可以得到颜色列表和尺码列表。用户选择后，页面把当前属性重新拼成字符串，在 SKU 列表中找到对应项，拿到真正提交的 skuId。

Set 只解决选项去重，没有解决组合是否有效。`颜色:黑;尺码:M` 和 `尺码:M;颜色:黑` 语义相同，但字符串顺序不同就匹配不到；而且颜色和尺码分别存在，不代表任意组合都有库存。当前找不到组合时还会保留上一次 SKU，可能出现页面选择和提交 skuId 不一致。

改进时可以固定属性顺序生成稳定组合键，建立组合到 SKU 的索引；每次选择后根据有效组合禁用不存在或无库存的选项。没有匹配结果就清空当前 SKU 并禁止购买，最终价格和库存仍由服务端校验。

## 回答要点

- 接口给出的每个 SKU 都是一组完整属性，例如“颜色:黑;尺码:M”。
- 前端把每条组合按分号和冒号拆开，再用 Set 收集每个属性下不重复的选项，这样可以得到颜色列表和尺码列表。
- 用户选择后，页面把当前属性重新拼成字符串，在 SKU 列表中找到对应项，拿到真正提交的 skuId。
- Set 只解决选项去重，没有解决组合是否有效。
