# 追问：AI Key 藏到服务端以后就安全了吗？别人直接请求 /api/ai 怎么办？

## 核心回答

把 Key 放到服务端，解决的是共享密钥直接下发给浏览器的问题，但没有自动解决接口滥用。当前服务端只接受 POST 和 JSON，检查浏览器请求是否同源，限制请求体、prompt 长度和模型选择，也对 IP 做了基础限流。不过这些检查不等于商城用户登录鉴权，别人仍然可能通过脚本直接请求接口，消耗应用的模型额度。

如果正式开放，我会在服务端验证用户身份，并增加用户额度、IP 额度和全站费用上限。还可以让前端只提交业务类型、商品 ID 或短关键词，由服务端自己组织完整提示词，减少接口被当成通用聊天服务使用的空间。现有代码还限制上游必须使用 HTTPS、输出最多 300 tokens，并把上游错误转换成简化提示，这些分别控制调用目标、单次成本和错误信息泄漏。
