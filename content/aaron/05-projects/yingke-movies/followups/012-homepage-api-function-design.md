# 追问：首页为什么拆成三个请求函数，不直接写一个循环？

## 核心回答

当前只有三个固定分类，拆成三个函数比较直观，能直接看出每个分类调用哪个 API。不过这三个函数的参数和结构基本相同，如果以后分类继续增加，重复方法和赋值会越来越多。我会考虑用分类配置数组保存分类 ID 和请求函数，再通过 `map` 生成 Promise 列表。是否现在就重构，要看分类是不是稳定的固定项；只有三个分类时，不需要为了抽象而增加过多复杂度。

## 回答要点

- 当前只有三个固定分类，拆成三个函数比较直观，能直接看出每个分类调用哪个 API。
- 不过这三个函数的参数和结构基本相同，如果以后分类继续增加，重复方法和赋值会越来越多。
- 我会考虑用分类配置数组保存分类 ID 和请求函数，再通过 map 生成 Promise 列表。
- 是否现在就重构，要看分类是不是稳定的固定项；
