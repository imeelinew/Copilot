# 购物车的嵌套数据和全选联动是怎么实现的？

## 30 秒回答

购物车是多层嵌套的列表结构，商品带选中状态和数量。我的设计原则是不单独存全选状态：全选和半选都是从子项派生的计算值——所有子项选中就是全选，部分选中显示半选；点全选就是批量把当前全选值取反设置到每个子项。总价、结算数量同样全部派生，保证任何操作后状态自动一致，不存在"改了数量忘了重算价格"这类问题。

## 标准回答

数据结构上，购物车列表的每一项包含商品信息、数量、选中状态，接口返回的是嵌套结构。更新某一项时我用 map 生成新数组、展开运算符替换目标项，保持不可变更新的习惯；这样每次变更都是一次明确的替换，逻辑可预测，也不会误改共享引用。

状态设计上我坚持"单一数据源加派生"：唯一真实的状态是每个商品的 selected 和 count，全选、半选、总价、件数全部是计算属性。勾选单个商品、修改数量、删除商品，全选状态和金额都会自动重算，不需要在每个操作里手动同步，这就消除了状态不同步的整类 bug。

价格上要区分两层：页面展示的联动总价是前端按选中项实时算的，体验优先；但最终结算金额以下单接口返回为准。我明确不把前端价格当结算依据，因为优惠、库存、运费的可信来源都在服务端，用户本地改数据是防不住的。

交互细节上，快速连点加减按钮会有高频状态更新和请求，我会做轻量节流并在下单时重新校验；商品被删除时同步清理它的选中状态，避免脏数据。

## 回答要点

- 核心设计："单一数据源 + 派生状态"，全选不单独存。
- 不可变更新说清楚，顺便连接 React/Vue 的更新模型。
- 前端价格只管展示、结算以后端为准，体现安全意识。
