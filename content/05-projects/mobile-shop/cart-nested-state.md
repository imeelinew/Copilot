# 购物车的嵌套数据和全选联动是怎么实现的？

## 核心回答

购物车是个嵌套列表，每件商品带数量和选中状态。设计上我就守一条：全选不单独存。所有子项都选中，全选框自然就是亮的；部分选中就显示半选；点全选就是批量把每个子项设成同一个值。总价、结算件数也全是派生出来的计算值。

这样做的好处是，不管怎么操作——勾商品、改数量、删商品——全选状态和金额都自动是对的。不存在"改了数量忘了重算价格"这种 bug，因为压根没有需要手动同步的第二份状态。

改某一项的时候，我用 map 出新数组、展开运算符替换那一项，不直接改原数据。

## 展开回答

价格要分两层说：页面上联动显示的总价是前端算的，图个实时；最终结算金额必须以下单接口返回为准。优惠、运费、库存的可信来源都在服务端，用户本地改数据是防不住的，所以前端价格只能用于展示，这个边界我分得很清。

交互上，快速连点加减按钮会有高频更新，我做轻量节流，下单时再校验一次。删除商品时把它从选中集合里清干净，别留脏数据。
