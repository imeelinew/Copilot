# 为什么使用 sessionStorage 保存订单确认数据？

## 核心回答

因为用户从购物车或者商品详情页去确认订单时，需要把这次要买什么带过去，而且刷新页面以后，这些信息也得保留。如果只放在组件里，刷新就丢了，所以我用了 sessionStorage 暂存这次下单的参数。

从购物车过来，主要存的是选中商品的购物车 ID 和地址 ID；从商品详情页直接购买，就存商品 ID、规格 ID、数量这些信息。订单确认页拿到参数以后，再请求后端，获取商品详情和结算金额。

它只服务于当前这次下单，不需要一直保存。sessionStorage 在当前标签页刷新后还在，正常关闭标签页后会清除，比较适合这个场景。拿到创建成功的订单号以后，我也会主动把这份临时数据删掉。

## 展开回答

用户去修改地址再回来时，页面会重新获取地址列表，把最新的默认地址 ID 更新到参数里，再请求一次订单确认。如果本地已经没有下单参数了，就提示用户重新选择商品，并回到购物车。

这里本地保存的只是下单参数。价格是后端根据商品规格重新查询、计算的，提交订单时也会重新计算，不会拿浏览器里存的价格直接生成订单。
