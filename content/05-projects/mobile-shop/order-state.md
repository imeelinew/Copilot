# 为什么使用 sessionStorage 保存订单确认数据？

## 核心回答

用户从购物车或者详情页去确认订单时，需要把这次要买什么带过去，而且刷新以后也得保留，所以我用 sessionStorage 暂存下单参数。

从购物车过来，存的是购物车 ID 和地址 ID；直接购买时，存商品、规格和数量。确认页拿到这些参数以后，再请求后端获取商品信息和结算金额。拿到创建成功的订单号以后，就把临时参数删掉。

## 追问：为什么不用组件状态、URL 或 localStorage？

组件状态刷新就丢了，下单参数放 URL 里也比较零散，还得处理数组和对象。localStorage 会一直保留，而这份数据只服务于当前下单流程。sessionStorage 在当前标签页刷新后还在，正常关掉标签页后清除，比较符合这里的需要。

## 追问：用户去换地址，再回来怎么恢复？

确认页会重新获取地址列表，找到最新的默认地址，把地址 ID 更新到下单参数里，再请求一次订单确认。这样页面上的商品和金额，也会跟着后端最新返回的结果展示。

## 追问：用户修改本地价格怎么办？

本地保存的是商品 ID、规格和数量这些参数。后端会根据规格重新查询价格，订单确认和真正提交时都会计算金额，不会直接接受浏览器传来的总价。所以改页面上的价格，不等于改了最终订单金额。

## 追问：没读到数据或者用户取消支付怎么办？

没读到下单参数，会提示重新选择商品并回到购物车。订单创建成功、拿到订单号后就会清掉这份参数；后面即使取消支付，订单也已经存在，只是保持待支付，可以去订单列表继续处理。
