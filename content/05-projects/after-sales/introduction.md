# 介绍一下智服工单项目

## 核心回答

智服工单是一个售后服务管理项目，主要给客服、维修人员和管理员使用。前端用 Vue 2、Vuex 和 Element UI，后端有配套的 Node.js 服务。

业务上，客服先给客户和设备建档，遇到问题就创建工单，再分配给维修人员。维修完成后进入回访，确认解决以后结束工单。

我比较关注的是这中间的状态和权限：现在到哪一步、谁能操作、下一步能做什么，都有对应规则。页面只展示当前能做的操作，服务端也会再校验。另外会按问题类型设置处理时限，把超时工单标出来。

## 追问：这个项目最值得讲的亮点是什么？

我会讲工单流转。它需要同时看当前状态、操作人的角色，以及工单分配给谁。比如工程师可以开始处理、提交回访，但不能直接完成工单。状态更新还要和操作记录一起保存，出了问题能知道是谁、在什么时候做了什么。

## 追问：工程师为什么只能看自己的工单？

服务端查询列表和详情时，如果当前角色是工程师，会加上负责人等于当前用户的条件。修改状态时也会再检查负责人，所以不能只靠前端把其他人的工单藏起来。

## 追问：Vue 2 里怎么组织这些页面？

页面用 Options API 组织，data 保存表单、列表和弹窗状态，computed 计算当前用户能做哪些操作，methods 里处理请求和提交。登录用户等共享信息通过 Vuex 读取，路由和页面再根据角色判断访问和按钮展示。

## 追问：超时提醒是怎么算的？

创建工单时，后端读取问题分类的处理时限，算出截止时间并保存。查询时再判断截止时间是否早于数据库当前时间，而且工单还没完成、没取消。前端拿这个结果显示超时标签，也能筛选超时工单。

## 追问：两个人同时操作会不会覆盖？

更新时会开启事务，用 FOR UPDATE 锁住工单这一行，再按数据库里的最新状态检查操作是否合法。状态更新和操作记录一起提交。当前还没有让前端提交打开页面时的版本号，所以不能说已经完整检测了所有旧页面提交。
