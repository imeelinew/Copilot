# Vue 大列表和 v-for 渲染慢时怎么排查？

## 核心回答

先看数据量、每行组件复杂度和更新频率，再决定稳定 key、分页、虚拟滚动或组件拆分。key 要代表业务实体，不能在排序或插入时使用 index；传给子组件的 props 尽量稳定，避免父组件小变化让整列都更新。长列表还要限制图片、阴影和同步计算，优化后用 Performance 和真实设备测滚动帧率、内存和交互延迟。

## 追问：虚拟列表有什么代价？

它只渲染视口附近的行，能降低 DOM 数量，但需要估算行高、处理动态高度、键盘焦点和滚动定位。读屏器、复制全部文本和浏览器查找也可能受影响。数据量不大时，先分页或减少每行工作往往更简单，不能看到“虚拟”两个字就直接上。

## 追问：watch 深度监听会拖慢吗？

深度监听会遍历对象并在相关变化时触发，数据大或更新频繁时成本明显。能监听具体字段就不要 deep；需要比较复杂对象时，可以先计算出稳定的摘要或按事件显式通知。性能问题要用 flame chart 证实，不能只凭 API 名字判断。
