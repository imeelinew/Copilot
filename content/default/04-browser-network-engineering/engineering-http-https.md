# HTTP 和 HTTPS 的区别？HTTPS 是怎么保证安全的？

## 核心回答

区别说三层就够了：HTTP 明文传输，默认端口 80；HTTPS 是在 HTTP 外面套了一层 TLS（老早以前叫 SSL），默认端口 443。HTTP 有三个老毛病——明文可被窃听、内容可被篡改、对端可能是假的；HTTPS 对应给了三样：加密、完整性校验、证书验身份。

加密是混着用的。非对称加密安全但慢，只用在最关键的一步：TLS 握手时交换材料、协商出对称密钥；之后真正的数据全用这个对称密钥加密，快。大概是客户端和服务器各出一个随机数，配合证书里的公钥协商出会话密钥，后面就靠它。

防冒充靠证书。服务器把域名、公钥这些信息拿去让 CA 签名，客户端收到证书后用内置的 CA 公钥验签，验不过就报错拦截，假域名拿不出有效证书。代价也提一句：握手多一次往返，加解密有 CPU 开销，但现在都很便宜了，浏览器里的 HTTP/2、HTTP/3 基本只在 HTTPS 上跑。

## 展开回答

面试官常追问为什么不全用非对称加密：太慢，而且会话密钥协商完就换对称加密了，非对称只在交换密钥那一刻露面，安全和性能都兼顾。

TLS 1.3 可以当亮点讲：握手压缩到一次往返，恢复连接甚至 0-RTT，还砍掉了一批不安全的老算法，只保留有前向安全的密钥交换。另外 HTTPS 只保证传输安全，本机装了抓包工具的证书照样能看明文，所以本地抓包能看到、不代表线上链路不安全。
