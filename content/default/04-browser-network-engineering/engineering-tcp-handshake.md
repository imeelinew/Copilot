# TCP 三次握手和四次挥手讲一下？

## 核心回答

握手是建立连接。客户端发 SYN 说我想连；服务器回 SYN+ACK，意思是收到、我也想连；客户端再回 ACK，连接才算建好。为什么是三次：TCP 是全双工，双方都得确认"我能发你能收、你能发我能收"，两次只能确认三件事，服务器还不知道自己发的包对方收没收到。而且只要两次的话，一个在网络里迷路很久的旧 SYN 晚到了，服务器一回应就当连接建好干等着，白白占资源；三次让客户端也有机会拒绝这个失效请求。

挥手是断连接，要四次。客户端发 FIN 说我不发了；服务器先回 ACK 表示知道，但它自己可能还有数据没发完；等真发完了，服务器再发自己的 FIN；客户端回 ACK，连接关掉。中间 ACK 和 FIN 必须分开，所以比握手多一次。

客户端发完最后的 ACK 会进 TIME_WAIT，等 2MSL 才真正关。一来万一 ACK 丢了，服务器重发 FIN 还能补上；二来让这条连接的旧报文在网络里自然消亡，不污染之后复用同端口的连接。

## 展开回答

可以顺手把 HTTP 和它的关系带上：HTTP/1.1 默认长连接，不是每个请求都握一次手；HTTP/2 多路复用，一条连接跑很多请求；HTTP/3 干脆把传输层换成基于 UDP 的 QUIC，握手更快、切网络还不断线。问握手最后往往就是想听这些落地的东西。

TIME_WAIT 等的 2MSL 也能展开：MSL 是报文的最大存活时间，一来一回正好两个，保证"我发的最后一个 ACK 要么送到了，要么对方重发的 FIN 还活着"。
