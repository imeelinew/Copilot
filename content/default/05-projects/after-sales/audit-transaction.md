# 智服工单状态变更为什么要事务和操作记录？

## 核心回答

状态变更不是只改一列：要先锁住工单，确认当前版本、操作者和允许的状态转移，再更新状态和 version，同时写操作记录，最后提交事务。智服工单的 controller 使用 `FOR UPDATE` 和版本条件来处理并发，状态规则和角色规则也分别校验。这样两个请求同时操作时，后到的请求会因为版本或当前状态变化而失败，而不是静默覆盖。

## 追问：状态更新成功、审计写失败怎么办？

如果审计是合规要求，状态和记录应该在同一事务里，任一步失败就回滚；不能先返回成功再“有空补日志”。如果记录要写外部系统，则在本地事务里写 outbox，再由可靠任务投递并重试。当前代码路径是同一数据库事务，我会继续用集成测试确认异常回滚确实覆盖了两张表。

## 追问：FOR UPDATE 和 version 各解决什么？

行锁让同一时刻的事务看到并修改同一条记录时有明确顺序，version 条件则把页面拿到的旧版本显式带进更新，能识别长时间打开的旧页面。只靠前端禁用按钮不可靠，只靠 version 也要确保读取、校验、写入和审计处在同一事务边界里。
