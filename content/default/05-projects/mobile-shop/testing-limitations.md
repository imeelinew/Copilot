# 轻购目前怎样测试，哪些地方还缺验证？

## 核心回答

我会把商品筛选、价格计算、请求竞态和购物车扁平化这类规则放在单元测试；接口层验证认证、错误码和订单状态；再用少量 E2E 走登录、搜索、加入购物车和确认订单。当前代码里能看到业务路径，但我不会把“页面能跑”说成已经有线上验证。库存原子扣减、重复提交、真实支付回调和第三方 AI 的稳定性，仍需要集成或契约测试补上。

## 追问：购物车最值得测哪几条？

至少测全选和半选、数量边界、商品失效、快速连续修改、总价刷新失败和 checkout 数据恢复。请求测试要故意让旧响应晚于新响应，确认不会覆盖；服务端还要验证用户不能读取或修改别人的 basket。每条测试都断言用户可见状态，而不是只看某个内部变量。

## 追问：为什么支付不能只测按钮？

支付涉及重复通知、验签、超时和订单状态机，单击按钮只能证明前端发过请求。当前轻购是模拟状态流转，没有真实平台回调，所以我会把真实支付列为未接入，并设计接口契约测试覆盖成功、失败、重复回调和查询恢复，再在沙箱环境做一次冒烟。
