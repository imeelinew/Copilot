# 轻购下单时商品、SKU 和库存怎样重新校验？

## 核心回答

确认订单时服务端按当前用户查询购物车，再重新读取商品和 SKU，过滤不存在或不再可售的项，并把数量限制在当前库存范围内。订单金额也在服务端计算，前端传来的名称、价格和总价不能作为结算依据。写订单和订单项的过程放在事务里，失败时回滚，地址则保存成当时的 snapshot，避免用户以后改地址导致历史订单被改写。

## 追问：现在有没有真正扣库存？

我核对到的现有下单代码重点是重新 hydrate 商品、SKU 和数量，并在事务中写订单数据；没有看到完整的库存原子扣减或锁定流程。所以面试时我会明确说这部分仍有超卖风险，不能把“校验库存”说成“已经保证库存”。要补齐，需要在同一事务里按 SKU 做条件扣减或锁定，并补并发集成测试。

## 追问：用户重复点击提交怎么办？

前端可以在提交期间禁用按钮，但这只能改善体验。服务端还需要幂等键或订单请求号，重复请求返回同一个结果，并在事务中保证订单项不会重复写入。网络超时后页面不能直接假设失败，应该先用请求号查询结果，再决定是否允许重试。
