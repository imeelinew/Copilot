# 轻购的前端请求层怎样统一处理认证和错误？

## 核心回答

轻购的请求封装用 Axios 统一读取环境里的 baseURL，设置 5 秒超时，并在有 token 时加 `Authorization: Bearer`。响应层同时看 HTTP 状态和业务返回码，遇到 401 或约定的登录失效码就清理 token 并跳登录；其他错误交给页面决定是 toast、空态还是重试。这样页面只处理自己的业务状态，不需要每个接口都重复写认证逻辑。

## 追问：为什么要同时判断 HTTP 和业务码？

HTTP 200 只说明请求到达并返回了响应，有些接口会在业务体里表达失败；反过来网关也可能直接返回 401、403 或 5xx。两层都判断，才能把登录失效、参数错误和服务异常区分开。错误对象要保留可操作的信息，但不要把后端堆栈直接展示给用户。

## 追问：超时后是否应该自动重试？

读接口遇到明确的网络抖动可以有限重试，并带退避和幂等保护；创建订单、支付这类写操作不能因为超时就盲目重放。当前封装的超时是 5 秒，页面需要提供重试入口，并在重试前重新确认购物车和登录状态。更完整的重试策略应由接口契约配合，而不是请求层一刀切。
