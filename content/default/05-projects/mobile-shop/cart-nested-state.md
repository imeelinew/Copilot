# 购物车的嵌套数据和全选联动是怎么实现的？

## 核心回答

购物车数据有好几层，店铺下面还有分组，分组里才是商品。我保留这个结构展示，再用 computed 把商品整理成一个列表，方便统一处理勾选。

每件商品都有选中状态，全选也是算出来的：列表不为空，而且所有商品都选中，全选框才勾上。点全选时一起修改商品的选中状态。金额则是把选中商品的购物车 ID 传给后端，拿接口返回的总价；改数量成功以后也会重新获取。

## 追问：整理成新列表以后，为什么还能改原商品？

因为列表里放的还是原来那些商品对象，没有把商品深拷贝一遍。修改选中状态时，改的是同一个对象，Vue 会跟踪这个变化，原来按店铺展示的页面也会更新。

## 追问：为什么全选用 computed，总价却用接口？

全选完全可以从当前商品的选中状态判断，没必要再单独保存一份。总价在这个项目里由后端提供，前端监听选中的购物车 ID，变化时请求金额接口；一件都没选就直接显示零。

## 追问：用户一直点加减，会不会重复请求？

我用 Set 记录正在修改的商品 ID，请求没结束时先禁用对应的加减按钮。即使又进入处理函数，也会检查这个 ID，避免重复提交。同一件商品改完以后才恢复按钮，其他商品还可以操作。

## 追问：半选和删除后的选中状态怎么处理？

当前做了商品勾选和全选，没有做半选样式。要加半选，可以判断至少选了一件但没有全部选中。删除商品以后会重新加载购物车，当前实现也会把选中状态重置；如果要保留其他商品的勾选，可以先记下它们的 ID 再恢复。

## 追问：总价接口返回乱序怎么办？

当前总价请求还没有单独做乱序保护。如果快速切换勾选，确实可能出现旧金额后返回的问题。要补上，可以给每次金额请求加编号，只让最后一次更新总价；取消旧请求也可以一起做。这是购物车目前还需要改进的地方。
