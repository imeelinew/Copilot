# 轻购发布和线上故障你会怎么排查？

## 核心回答

我会先区分是前端资源、代理、接口还是数据问题。先看浏览器 Network 的首个失败请求和响应，再核对构建版本、反向代理和服务端日志；如果是新 chunk 找不到，检查 HTML、CDN 缓存和旧页面是否混用了不同版本。前端只做一次旧 chunk 重试并给刷新入口，不能无限 reload。回滚要能恢复到上一份前端产物和服务端兼容版本，再补记录和复盘。

## 追问：图片代理和 API 代理分别有什么坑？

图片代理要考虑缓存、来源白名单和响应类型，不能变成任意 URL 的 SSRF 入口；API 代理要限制路径、方法、超时和请求体，并把客户端错误与上游错误区分开。环境变量只放可公开的前端配置，密钥留在服务端。排查时优先用一个可复现请求验证，不在生产直接改一堆配置。

## 追问：你会怎样验证恢复？

用固定版本在干净浏览器和旧页面各走一遍登录、搜索、下单关键链路，检查资源、接口、错误提示和数据一致性。部署后观察错误率、chunk 失败率、接口 5xx 和关键转化，不只看“页面能打开”。如果不能执行真实线上演练，就明确说明验证范围和未覆盖部分。
