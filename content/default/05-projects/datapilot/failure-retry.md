# 城市视图首页多接口请求失败时怎么降级？

## 核心回答

首页卡片和地图环境数据不是一个整体，我会按业务重要性拆开处理。城市基础列表失败时给出页面级错误和重试；某个环境接口失败则保留城市点位，给对应卡片显示“暂时不可用”，其余数据照常展示。已核对的地图代码使用 `Promise.allSettled` 处理部分成功，并在组件卸载时取消请求。重试要有限次、带退避，而且不能覆盖用户已经看到的新一轮结果。

## 追问：为什么不用一个 Promise.all？

Promise.all 任何一项 reject 都会让整体失败，用户会看不到本来已经成功的城市或卡片。allSettled 能拿到每项状态，适合大屏这种“局部有价值”的页面。不过登录、保存配置这类必须整体成功的操作仍然应该用 all 或明确的事务接口，不能为了展示部分数据到处吞错。

## 追问：loading 应该怎么设计？

页面首屏 loading 和单卡刷新状态分开，避免一张卡重试时整页闪烁。请求过期或切换城市后，旧结果要带请求版本检查；失败时保留上一份带时间的数据显示“数据可能过期”。用户点击重试后要能看到正在重试和最终结果，不能只在控制台打印错误。
