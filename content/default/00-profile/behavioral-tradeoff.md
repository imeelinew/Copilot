# 讲一次你在两个方案之间做取舍的经历

## 核心回答

城市视图的图表数据变化时，我可以每次销毁并重新 init，也可以复用已有 ECharts 实例只更新 option。我选了后者，因为图表容器和事件没有变化，重复初始化只会增加资源和清理风险；数据层变化用 setOption 更合适。前提是要在尺寸变化、主题切换和组件卸载时分别处理 resize、重建和 dispose，不能把“复用”当成永远不重建。

## 追问：你怎么判断这个取舍有效？

我会用 Performance 和 React Profiler 对比更新次数、脚本耗时、内存和交互响应，再在窗口缩放、空数据和快速切换图表时观察是否残留事件。没有测量时只能说是合理假设，不能直接宣称性能提升了多少。选择记录成代码注释或文档，后续换图表库也容易复查。

## 追问：什么时候会反过来选择重建？

配置类型、主题或底层实例无法安全增量更新，或者旧 option 残留会造成错误时，我会销毁后重建，并确保旧实例和监听器已经清理。性能不是唯一目标，状态正确和维护成本同样重要。取舍要跟实际更新频率和数据量一起看。
