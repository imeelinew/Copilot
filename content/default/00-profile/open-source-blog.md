# 聊聊你的 GitHub、博客和个人网站？

## 核心回答

GitHub 近一年提交差不多一千次，主要就是三个项目的持续迭代。我的习惯是小步提交，一个提交只做一件事，修个 bug 或者加个小功能就提一次，所以提交曲线是连续的。我觉得诚实的提交历史比好看但失真的记录有用，回看的时候能知道每次改动是为什么。

个人网站 elinew.tech 放作品和项目入口，域名、解析、部署都是自己弄的。博客主要写两类：踩过的坑，和对某个知识点的理解。写作对我来说是检验——写不清楚就说明还没真懂，那就回去再学。

## 追问：项目里有什么值得拿出来讲的实现？

轻购的智能导购可以结合代码讲。从用户的一句需求开始，看模型提取了哪些条件，后端怎么筛商品，再看页面上的匹配信息从哪里来。这样可以把功能效果和具体实现对应起来。

## 追问：如果把这个功能写成技术文章，会怎么写？

我会先用一个选购例子说明需求，再画清前后端的数据流程，最后讲两个具体问题：推荐理由怎么对应商品信息，以及模型失败时怎么继续返回基本推荐。也会注明当前规则匹配的局限，避免把效果说得过满。
