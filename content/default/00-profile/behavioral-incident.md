# 讲一次你排查并修复问题的经历

## 核心回答

轻购搜索页有一次连续输入时，偶尔会出现后输入的词却显示了前一个词的结果。我先在 Network 里看时间线，确认不是接口返回错，而是旧请求比新请求晚结束，最后一次响应把页面覆盖了。后来我同时加了 300 毫秒防抖、AbortController 和请求编号校验：减少无用请求，能取消的旧请求主动取消，即使旧响应回来也不会提交。改完我用慢响应和快速输入反复测，才把这个问题算解决。

## 追问：这件事里你学到什么？

我当时只想到防抖，后来发现防抖解决的是“什么时候发”，不解决“已经发出的请求谁先回来”。把调度、取消和结果提交分开想，问题就清楚了。以后遇到任何搜索或联动请求，我都会先画出可能的时序，再决定是否需要请求编号和清理。

## 追问：如果重新做会怎么改？

我会把这套逻辑抽成可复用的请求 composable，并给它补一个旧响应晚到的自动化测试。还会把取消视为正常状态，不在用户主动清空输入时弹错误。现在的实现能保护页面结果，服务端是否已经处理完请求则要由接口幂等和限流另行保证。
