# 讲一个你最近主动补上的知识点

## 核心回答

我最近系统补的是 React 的 Effect 边界。以前容易把“数据变了就 useEffect”当成习惯，后来按官方文档把事件处理、派生数据和同步外部系统分开，再在城市视图里对照地图、ECharts 和定时器的清理。我的学习方式一般是先用一个小例子复现，再回到项目里找同类代码，最后写成能回答“为什么”和“失败时怎么办”的笔记，而不是只记 API 名字。

## 追问：怎么证明自己真的学会了？

我会主动写一个会产生旧闭包或竞态的例子，再用请求取消、依赖和清理把它修掉，并解释每一步的因果。能在新场景里判断“这里不需要 Effect”，比背一个固定模板更能说明理解。测试和代码 review 也能暴露自己没有想到的边界。

## 追问：如果时间很紧怎么学习？

先围绕当前任务找最小必要范围：官方概念、一个可运行例子、项目里的落点和一个失败边界。暂时不扩展到所有高级 API，先把能影响交付的部分验证清楚。任务完成后再把没展开的内容列成下一轮学习清单。
