# 遇到意见不一致时你会怎么推进？

## 核心回答

我会先把分歧拆成目标、约束和可以验证的事实，而不是争“谁的写法更漂亮”。比如有人担心一个组件拆分会影响性能，我会先确认真实瓶颈，再用最小复现或 Profiler 对比；如果只是团队规范问题，就按维护者和项目约定来。讨论结束后把决定和原因写进 PR 或文档，之后发现证据变了也可以回头修正。

## 追问：如果 review 连续被打回呢？

先确认是同一类问题没有改干净，还是我没有理解团队真正关心的约束。可以把修改点逐条回应，必要时约维护者十分钟对齐示例，再拆成更小的提交。被打回本身不是失败，反复用同一方式提交、却不总结规则才是问题。

## 追问：没有真实团队经历怎么回答？

我会诚实说目前主要是在个人项目和学校活动中练习协作，没有把它说成正式团队冲突；然后讲清楚自己会采用的推进方式，并用 Git 分支、清晰提交、请求参数和复现步骤降低沟通成本。入职后再按团队流程校准，而不是假装已经经历过所有场景。
