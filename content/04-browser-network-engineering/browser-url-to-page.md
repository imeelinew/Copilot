# 从输入 URL 到页面展示，中间发生了什么？

## 核心回答

这是道大串联的题，我按顺序讲。回车之后浏览器先看本地有没有缓存：强缓存没过期就直接用，连请求都不发；过期了走协商缓存去服务器问一句。没有缓存或者要更新，就开始 DNS 解析，把域名换成 IP。顺序是先查浏览器和系统的 DNS 缓存，再看 hosts 文件，都没有就把查询交给本地 DNS 服务器，它替我一级级问上去，最后拿到 IP。

拿到 IP 就和服务器建 TCP 连接，经典的三次握手。如果地址是 HTTPS，TCP 之上还要再做一次 TLS 握手，验证证书、商量出对称加密的密钥。然后浏览器发 HTTP 请求，服务器处理完把 HTML 回给浏览器。

接下来是渲染的事：解析 HTML 建 DOM 树，解析 CSS 建 CSSOM，两者合成渲染树，然后算布局、绘制、合成上屏，过程中遇到 js、CSS、图片再按需去下载。最后连接闲置一段时间，四次挥手断开。补充一句，现在主流网站是 HTTP/2，多个请求复用一条连接；HTTP/3 换成了跑在 UDP 上的 QUIC，把传输握手和 TLS 合到一起，首次连接更快。

## 展开回答

面试官真正想看的是每一环能不能单独展开。比如 DNS 那段可以接 CDN：很多域名会通过 DNS 调度到离用户最近的 CDN 节点，加载加速从这一步就开始了。TCP 那段会接到三次握手为什么是三次，HTTPS 会接到加密原理，渲染会接到渲染流程和重排重绘。所以我把这道题当目录用，每一环都能往下再讲一个完整的题。

有个细节能体现理解：DNS 查询默认走 UDP 53 端口，因为请求小、要快，丢了大不了重问；只有区域传送这种大数据量场景才用 TCP。
