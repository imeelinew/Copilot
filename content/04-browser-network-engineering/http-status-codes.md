# 常见的 HTTP 状态码有哪些？

## 30 秒回答

按类记：2xx 成功，常见 200、201、204；3xx 重定向，301 永久、302 临时、304 协商缓存命中；4xx 客户端问题，400 参数错误、401 未认证、403 无权限、404 不存在、409 冲突、429 限流；5xx 服务端问题，500 内部错误、502 网关拿不到有效响应、504 上游超时。我项目里处理最多的是 401——统一跳登录；还有 409——工单并发冲突时提示刷新。

## 标准回答

我更想按"我处理过"的方式讲。

401 和 403 的区别在项目里很实际：401 是"没登录或凭证失效"，我的 Axios 响应拦截器捕获后清除本地会话、跳转登录页并带上回跳地址；403 是"登录了但没权限"，不该踢去登录页，而是提示无权访问。这两个混在一起处理是常见的新手错误。

409 在智服工单里有真实用途：工单状态更新用 version 做乐观锁，两个人同时操作同一工单时，后提交的那个请求命中不了 version 条件，后端返回 409，前端提示"工单已被他人处理，请刷新"，避免静默覆盖别人的结果。

301 和 302 的区别是永久与临时：301 浏览器和搜索引擎会记住新地址，之后可能不再访问旧 URL；302 每次都还访问原地址。做域名迁移用 301，活动跳转这类临时逻辑用 302。

304 是协商缓存命中，配合 Cache-Control 理解；502 和 504 都指向服务端链路，502 是网关从上游拿到无效响应，504 是等上游超时，排查时说明问题不在前端，我把现象和接口信息反馈给后端。

## 回答要点

- 不要平铺罗列，按 401/403、409、301/302、502/504 这几组"有故事的"展开。
- 401 和 403 的差异化处理是真实项目细节。
- 409 直接呼应工单乐观锁，引到自己的亮点。
