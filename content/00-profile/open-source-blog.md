# 聊聊你的 GitHub、博客和个人网站？

## 30 秒回答

我的 GitHub 是 imeelinew，近一年提交接近一千次，主要是三个项目的持续迭代，习惯是小步提交——发现问题、修复、记录，所以提交曲线是连续的。个人网站 elinew.tech 放作品集和项目入口，部署和域名解析都是自己配的。博客写开发中踩的坑和对原理的理解，对我来说写作是验证理解的方式：一个知识点如果写不清楚，说明我还没真正懂，我会回去重新学。

## 标准回答

这三个平台对我承担的角色不一样。

GitHub 是工作台。三个项目和日常实验都在上面，我保持小步提交的习惯，每个提交聚焦一件事，这样回看历史时能清楚定位每次改动的意图。提交多不代表代码多，很多提交是修复和重构，我认为诚实的提交历史比漂亮但失真的记录更有价值。

博客是检验场。我写的多是"我遇到什么问题、怎么定位、最后怎么解决"这类内容，比如防抖在搜索联想里的应用、部署时的缓存问题。写作过程经常暴露理解漏洞，倒逼我查文档和源码，这是我最重要的学习方法。

个人网站是名片。从域名、解析到部署都是我自己完成的，它让我完整走过一次线上服务的流程，也让我养成了"做的东西要能被别人访问到"的习惯。

不过我也清楚，我的开源目前以个人项目为主，还没有给知名开源项目提交过 PR，这是我下一步想补的，从文档和小 issue 开始参与。

## 回答要点

- 三个平台各有定位，不要笼统说"我会持续输出"。
- 承认提交多主要是个人项目，体现诚实。
- 博客的作用落在"写作验证理解"这个具体方法上。
